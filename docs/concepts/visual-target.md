# 视觉目标卡 · 住院费用争议解释系统

> 本文件是**视觉目标**（设计意图），不是实测截图。真实运行截图落在 `docs/screenshots/`，
> 由 Phase 4 采集桌面程序真实渲染结果。本环境无图像生成能力，故此处只保留结构化卡片，
> **不伪造概念图、不放占位图**。

## 画面类型

桌面窗口（Electron 主窗口 + 系统托盘常驻）。**不是** Web 控制台，**不是**终端表格。

## 三个状态

### 1. 起始态

- 桌面右下角托盘常驻图标（呼吸一次的蓝色圆点）。
- 双击唤出主窗口：左侧是**待办咨询列**——每行显示住院号后 4 位、家属质疑摘要、停留时长、
  一枚彩色分类点（绿 = 可当场解释 / 琥珀 = 需转医保办 / 红 = 需人工判断）。
- 右侧为空态提示：「把家属的话粘贴进来，或拖入录音转写文件」。
- 窗口顶栏：「住院费用争议解释」标题 + 一个「+ 登记咨询」按钮。

### 2. 首个可用瞬间

- 收费员粘贴一段家属质疑 → 点「归因」→ 右侧变成**逐项解释稿**，每条明细分三块：
  - 「这笔 3,200 元 / 头孢呋辛钠 0.5g×6（明细行 7）」
  - 「对应口径：结算清单 · 医疗收费信息 · 西药费」
  - 「为什么不能报医保：医保支付范围外（第 38 条第 6 项）」
- 每条右侧一个小方块「✓ 当场解释」。
- 顶部一行汇总数字：**归因 12 条 / 当场解释 9 / 需转医保办 2 / 需人工判断 1**。
- 右下角一条细进度条：12 条已归因到 12 条明细行。

### 3. 成形态

- 左侧咨询列变成**状态流水线**（待答复 → 草稿待确认 → 已答复 / 已转办 / 已关闭），
  每条咨询行右侧带一枚灰底引用计数「引用 3 条口径」。
- 窗口顶栏多一个「待打印稿 1」角标；托盘图标变实心蓝。
- 点开已答复咨询，右侧显示当时的解释稿、引用清单（价目编码 + 清单字段号 + 模型版本）、
  转办工单号与回执状态 —— 这就是「事后家属再问，不用重来一遍」的那一屏。

## 视觉语言

| 元素 | 取值 |
|------|------|
| 底色 | `#F5F7FA`（浅灰蓝，非纯白，减轻窗口长时间注视疲劳） |
| 卡片 | `#FFFFFF` |
| 主色 | `#1F6FEB`（主按钮与托盘点） |
| 分类点 | 绿 `#17A673` / 琥珀 `#D98A00` / 红 `#D64545` |
| 引用文字 | `#5B6B7C`（比正文浅一档，让「解释」与「依据」层级分开） |
| 分隔线 | `#E3E8EF` |

- **字体族**：中文 `PingFang SC`，正文 13px / 行高 1.6；数字与编码（住院号、价目编码、清单字段号）
  用 `SF Mono` 等宽，保证竖排对位。
- **金额**：右对齐、等宽、**不加千分位**（避免与 HIS 票据口径不一致）。
- **信息层级**：
  1. 最显眼 = 右侧解释稿的金额行与分类点（收费员只关心「这条要多少钱、能不能当场说」）；
  2. 第二层 = 顶部四个汇总数字；
  3. 第三层 = 引用依据（小字灰）；
  4. 最弱 = 左侧列表的住院号后 4 位。
- **留白密度**：中高——解释稿每条之间留 12px，一屏约容 8 条明细行；
  折叠「引用」区默认展开第一条，其余收起，避免一眼看到几百行依据。

## 必须可达的约束

只允许当前技术栈真能做出来的元素。

**可做**：Electron 窗口 + 系统托盘（`tray` API）、本地 SQLite 台账、明细列与解释稿两栏布局、
等宽数字、分类点色块、拖拽文件入窗、打印 / 导出 PDF（`webContents.printToPDF`）。

**不可做**（本轮不画）：实时协同光标、语音波形动画、WebGL 3D、动效图表、在线多人同时编辑 ——
这些在「单岗位单机常驻小工具」形态里不可达，画了就是假。
